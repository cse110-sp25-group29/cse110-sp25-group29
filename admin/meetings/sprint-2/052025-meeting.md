## Topics

## What Happened

- Discussed prioritization using MoSCoW categories: Must haves, Should haves, Could haves, and Won’t haves.
- Agreed that using numerical values (1–3) is a more practical method for setting priorities:
  - **1** – Low priority (e.g., non-MVP features, distant future tasks).
  - **2** – Default priority (e.g., ADRs, stand-up notes, horizon tasks).
  - **3** – High priority (e.g., tasks with imminent deadlines).
- Emphasized that documentation and notes shouldn’t always be marked low priority as they will need to be merged eventually.
- Prioritization should consider both **urgency** and **size**.
- Sizing tasks:
  - Default scale uses **1 point = 1 hour**.
  - Each team can define what size means for their specific workflow.

## Things to Do

- All teams adopt the 1–3 priority scale and urgency/size framework.
- Teams determine and document their own task sizing definitions.
